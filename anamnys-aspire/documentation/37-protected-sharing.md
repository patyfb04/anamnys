# Chapter 37: Protected Sharing (F-17 + F-18)

How a provider shares a signed issued document with a named recipient through an opaque link and a separate
password, only after recording the patient's authorization. Last checked against the code on 2026-11-01 (branch
`feature/protected-sharing`). Design: `design/specs/2026-11-01-protected-sharing-design.md`.

What a future change has to respect: no link exists without an authorization record (section 3); the token and the
password never go in a log, a URL of the API or an audit value (sections 5 and 14); every dead link answers the same
404 (section 6); a counted wrong password or view is never undone (section 6); and the shared document is always the
version that was signed when the link was made (section 9).

---

## 1. Purpose and scope

Done when (backlog): sharing is unavailable until an authorization record exists; a signed report can be shared,
opened with a password delivered through another channel, watermarked, logged and revoked, with each step in the
audit trail.

Out of scope, by the backlog: sending the document by e-mail (the provider copies the link and the password and sends
them through channels of their own), and any sharing with no authorization record. The recipient has no account.

exists the migration stops instead of inventing a consent. The F-06 discard already removed share rows; it now also
deletes the attached term object (chapter 30).

## 3. The authorization record (F-17)

The provider records, for one signed document: recipient name (max 200) and role (max 100), purpose (max 500),
the authorization date (not in the future), how it was obtained (verbal in session, signed term, in writing), an
optional attached term and an explicit confirmation. There is one authorization per document, recipient and purpose
(case-insensitive); a second one answers 409 `authorization_exists` with the id of the first.

- Name and role refuse control and Unicode format characters (zero-width, direction overrides), because the name is
  printed in the watermark. The purpose may contain line breaks.
- The term is a PDF, JPG or PNG up to 20 MB, checked by magic bytes and extension, and **scanned with ClamAV inline
  before it is stored**, so nothing unscanned reaches the bucket. A scanner that cannot answer refuses the upload
  with 503 (fail closed). The key is `disclosure-terms/{providerId}/{authorizationId}`.
- The provider can open the term again: scoped, streamed inline with `no-store` and `nosniff`, no presigned link,
  audited `disclosure_term_opened` with the id only. It is readable for archived patients.
- Without an authorization, creating a link answers 409 `authorization_required`.

---

## 4. What can be shared, and why

Only **signed issued clinical documents** (F-05). Not session notes (they hold the provider's working record, and
a note is not an issued document), and not received documents (they belong to someone else). A draft answers 409
`not_signed`. The list endpoint returns `canShare` and `blockedReason` (`not_signed`, `document_superseded`,
`archived`) so the apps do not repeat the rules.

---

## 5. The link, the token and the password (F-18)

- **Token.** 32 random bytes (256 bits), base64url, 43 characters. Stored only as lower-case hex SHA-256; every
  lookup is by hash. It reaches the server only in POST bodies of the public API, never in an API URL.
- **Password.** Generated by the system, 16 characters from `abcdefghjkmnpqrstuvwxyzABCDEFGHJKLMNPQRSTUVWXYZ23456789`
  (55 symbols, none of `0 O o 1 l I i`; about 92 bits). Shown once.
- **Argon2id** (`Konscious.Security.Cryptography.Argon2` 1.3.1): **memory 19456 KiB (19 MiB), 2 iterations,
  parallelism 1**, 16-byte salt, 32-byte hash (the first configuration of the OWASP Password Storage Cheat Sheet).
  Stored as PHC text `$argon2id$v=19$m=19456,t=2,p=1$salt$hash`, so the cost can rise later and old hashes still
  verify. Compared with `CryptographicOperations.FixedTimeEquals`.
- **Options.** Expiry 7 days by default, 1 to 30 (the server rejects more). Optional view cap, at least 1. Download
  off by default.
- Creating a link returns `url` and `password` once, with `Cache-Control: no-store`. The password is not stored in
  clear and cannot be shown again.
- Creating a link takes an Argon2 slot too (section 8) and answers 429 `busy` when none is free.

The provider app keeps the password only in the modal's state, never in a query cache or browser storage.

## 6. The public flow

The recipient opens `/patient/s/{token}` in the patient app (no login), types the password and gets the PDF in the
same POST response. Nothing is stored for the download: no grant, no URL, no presigned link. The PDF is rendered
for each opening from the database row, inside the transaction, so a failed render uses no view and logs no opening.

- **Check.** `POST /api/public/shares/check` answers `{ "available": true }` and nothing else before the password.
- **Identical 404s.** Unknown, expired, revoked, capped and blocked links all answer the same
  `share_unavailable` 404 (a test compares status, every header but `Date`, and the body, on check and open). Each of
  them also runs Argon2 once, on a dummy hash computed at startup, so the time matches a wrong password. An empty or
  over-long password costs one hash too.
- **Wrong password.** 403 `wrong_password` (403 so that no session-expiry handling fires on it). Wrong passwords
  are **cumulative over the life of the link**: a right password does not reset the count (decision, see section 15).
- **Lockout.** The fifth wrong password blocks the link (`BlockedAt`, outcome `blocked`); the next try is the plain
  404.
- **View cap.** A successful open counts a view. The cap is enforced atomically.
- **Concurrency.** The state check, Argon2 and the commit run under `SELECT ... FOR UPDATE` on the link row, so
  parallel guesses cannot pass the fifth wrong password and parallel opens cannot pass the cap (tested with 12
  parallel wrong passwords, exactly 5 counted, and 10 parallel opens on a cap of 3, exactly 3). The clock is read
  after the lock, so a link that expires during the wait is unavailable and uses no view.
- **Cancellation.** The request's cancellation is honoured up to the password check (queue, lookup, lock wait); from
  then on the attempt always commits, so dropping the connection cannot undo a counted wrong password.
- Headers on every answer that reaches the endpoint: `Cache-Control: no-store`, `X-Robots-Tag: noindex`,
  `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`.

## 7. Rate limits and the 429 answers

Per client, partitioned by `ShareNetwork.PartitionKey` (IPv6 by /64, IPv4-mapped addresses as IPv4):

| Route | Limit |
|---|---|
| `POST /api/public/shares/check` | existing `public` policy, 30 per minute per client |
| `POST /api/public/shares/open` | policy `share-password`, 10 per minute per client |
| both together | one global limit of 120 per minute on `/api/public/shares` |

Rate-limit 429 has no body and none of the share headers. A second 429 comes from the concurrency limiter
(section 8): `{ "message": "...", "code": "busy" }` with `Retry-After: 5` and `no-store`, returned before any
transaction or lock, with no attempt or view counted.

---

## 8. Concurrency limit

Argon2 spends 19 MiB per derivation on an anonymous route, so `ShareAttemptLimiter` (a `ConcurrencyLimiter`) allows
**4 running and 8 queued, oldest first**, for the whole process. The slot is taken before the row lock; an attempt
waiting on the lock keeps its slot and the next one gets 429 `busy` without a connection. Unknown and already-dead
tokens hash outside any transaction. While an attempt runs it holds one database connection for roughly 100 ms or
more, bounded by the rate limit and the limiter.

---

## 9. Watermark and superseded documents

Each opening renders the document PDF with the recipient name and the date and time (practice time zone) on **every
page**, centred on the page by explicit positioning (a test caught a first version that sat about 237 pt low). The
normal PDF (`DocumentPdf.Render(m)`) is unchanged; the sharing path uses `Render(m, watermark)`.

A corrected document does not change an existing link: it keeps showing the version that was shared, and the
provider's list says a newer version exists (`supersededBy`, with a link). A superseded document gets **no new
authorization or link** (409 `document_superseded`): sharing a known-outdated version looked wrong (decision beyond
the spec, confirmed by the user).

---

## 10. Archived patients and discard

An archived patient cannot get new authorizations or links (409 `archived`); existing links run until they expire,
and the term stays readable. The F-06 discard removes every link, authorization, access and the attached term
object, and its audit delete covers the new entries because they carry the document id.

---

## 11. The access log

`ShareAccesses` records the time, the outcome (`opened`, `bad_password`, `expired`, `revoked`, `cap_reached`,
`blocked`) and the user agent (512 characters at most). **There is no geolocation and no IP is stored.** Sending an
IP to a third party would be a new disclosure, and a local database needs a licence and updates; this is a decision
and a recorded gap. Dead links log one row per link and outcome per minute, so a scan of a dead link cannot flood the
table. The provider list shows the newest 100 accesses per link and the total in `accessCount`.

## 12. Endpoints

Provider (cookie session, `/api/phi/providers/me`; another provider's document or link is 404; audit values carry ids
only):

| Method and path | Body | Success | Errors |
|---|---|---|---|
| `GET documents/{documentId}/shares` | | 200 list | 401, 404 |
| `GET shares?status=active|all&page=n&patientId=` | | 200 overview page (section 13a) | 400, 401 |
| `POST documents/{documentId}/disclosure-authorizations` | multipart: `recipientName`, `recipientRole`, `purpose`, `authorizedAt`, `obtainedVia`, `confirmed`, optional `term` | 201 `{ "id" }` | 400, 404, 409, 503 |
| `POST documents/{documentId}/share-links` | `{ "authorizationId", "expiresInDays", "viewCap", "downloadEnabled" }` | 201 | 400, 404, 409, 429 |
| `POST share-links/{linkId}/revoke` | | 204 (also when already revoked, audited once) | 404 |
| `POST disclosure-authorizations/{authorizationId}/term/open` | | 200 file | 401, 404, 503 |

List response (accesses newest first):

```json
{ "documentId": "…", "canShare": true, "blockedReason": null, "supersededBy": null,
  "authorizations": [ { "id": "…", "recipientName": "Dr. Pedro Lima", "recipientRole": "Psiquiatra",
    "purpose": "Continuidade do cuidado", "authorizedAt": "2026-11-01T00:00:00+00:00",
    "obtainedVia": "verbal_session", "hasTerm": false,
    "links": [ { "id": "…", "status": "active", "createdAt": "…", "expiresAt": "…", "viewCap": 3, "viewsUsed": 1,
      "accessCount": 4, "downloadEnabled": false, "revokedAt": null, "blockedAt": null,
      "accesses": [ { "at": "…", "outcome": "opened", "userAgent": "Mozilla/5.0 …" } ] } ] } ] }
```

Link `status`: `active`, `revoked`, `blocked`, `expired`, `capped`.

Link creation response (`url` and `password` appear only here):

```json
{ "id": "…", "url": "https://host/patient/s/<43 chars>", "password": "<16 chars>",
  "expiresAt": "2026-11-08T15:00:00+00:00", "viewCap": 3, "downloadEnabled": false }
```

Errors of the provider routes:

- Authorization 400 `ValidationProblem` keys: `recipientName`, `recipientRole`, `purpose`, `authorizedAt`,
  `obtainedVia`, `confirmed`. 400 `{ message, code }`: `invalid_form`, `empty`, `too_large`, `type_mismatch`,
  `unsupported_type`, `infected`. 409: `not_signed`, `document_superseded`, `archived`, `authorization_exists` (with
  the existing `id`). 503: `scanner_unavailable`, `storage_unavailable`.
- Link creation 400 keys: `expiresInDays`, `viewCap`. 409: `authorization_required`, `not_signed`,
  `document_superseded`, `archived`. 429 `busy`.

Audit actions: `disclosure_authorized`, `share_link_created`, `share_link_revoked`, `disclosure_term_opened`.

Public (anonymous, `/api/public/shares`, body limited to 4 KB):

| Route | Body | Answers |
|---|---|---|
| `POST check` | `{ "token" }` | 200 `{ "available": true }`; 404 `share_unavailable`; 429 |
| `POST open` | `{ "token", "password" }` | 200 `application/pdf`; 403 `wrong_password`; 404 `share_unavailable`; 429 (no body, or `busy`) |

The 200 of `open` has `Content-Disposition: inline` when download is off and
`attachment; filename="documento-XXXXXXXX.pdf"` when on. That header is the app's signal for showing the download
button. Error bodies: `{ "message": "Senha incorreta.", "code": "wrong_password" }` and
`{ "message": "Este link não está disponível.", "code": "share_unavailable" }`.

## 13. Apps

Provider, signed document page: the card "Compartilhar" (`SharesCard`) is on every document. It shows the reason when
sharing is blocked (unsigned, superseded, archived) and no button. The flow has three steps: the authorization form
(submit disabled until every required field and the confirmation are set), the link options (expiry, view cap,
download), and a one-time screen with the link and the password and the warning to send them through different
channels. Closing the last screen by Esc, the backdrop or the X warns first; steps 1 and 2 cannot be closed while
their request runs, so a created password cannot be lost in flight. A 409 `authorization_exists` continues with the
existing id and says that the new data and term were not kept. The list shows each authorization (recipient, role,
purpose, date and how obtained, term mark), each link (status, expiry, views, download, the access log in a
`<details>`) and "Revogar" with a confirmation on active links. Authorization dates are shown in UTC, because the form
sends a plain date.

Patient app, public route `/s/$token`: password form (an empty password is blocked in the form, because it counts as
an attempt), pdf.js viewer (`pdfjs-dist` 6.4.299) that draws every page on canvases with no text layer, so it works on any device including Android Chrome; an object URL exists only for the download button and is revoked on cleanup, a download button only for `attachment`,
`noindex, nofollow` and `no-referrer` meta tags. It uses plain state, no query cache and no browser storage, and the
password state is cleared before every request. A wrong password (403) and any dead link (404) show the same "Link indisponível ou senha incorreta."; a
429, a network failure or a 5xx shows "Não foi possível abrir agora. Tente de novo em instantes." and keeps the form,
which reveals nothing about the link. The download is built from the blob already in memory; `open` is never called a
second time, because each call counts a view. Copy is in `pt.json`.

### 13a. The overview page "Compartilhamento"

Provider route `/secure-sharing` (the sidebar entry, feature flag `secureSharing`) lists every link the provider has
created, across documents. Links are still created only from a signed document's page; the page says so and links
back to the document.

- Endpoint `GET /api/phi/providers/me/shares?status=active|all&page=n&patientId=<id>` (`ShareService.ListOverviewAsync`).
  `status` defaults to `active` (any other value is a 400); `page` starts at 1 and is clamped to 1..10000; the optional
  `patientId` keeps only that patient's links, inside the provider's own scope (another provider's id returns nothing). Page size is 20,
  ordered by `createdAt` descending. Response: `{ items, total, page, pageSize }`.
- Each item: `linkId`, `documentId`, `documentKind`, `signedAt`, `patientId`, `patientName`, `recipientName`,
  `recipientRole`, `purpose`, `createdAt`, `expiresAt`, `status` (`active`, `expired`, `revoked`, `blocked`,
  `capped`, from the same rule as the document page), `viewsUsed`, `viewCap`, `downloadEnabled`, `accessCount`,
  `lastAccessAt` (the newest access of any outcome, null when none) and `newerVersionExists`.
- Scoping: only documents and patients of the signed-in provider; links of discarded patients are left out (the discard
  deletes them anyway). The `active` filter is a query over the same fields `DeniedOutcome` reads, so it agrees with
  what the public route does. Queries are bounded: one count, one page (join of link, document, patient and
  authorization) and one grouped count over the 20 links of the page.
- Like the other listings it writes no audit entry and logs no names; the response is `no-store`. The URL carries
  only `status`, `page` and the opaque `patientId`, never a name, document or recipient.
- Page: a patient search field (`PatientFilter`: type-ahead over the POST patient search from 2 characters, up to 8
  suggestions; Enter or a click applies the highlighted one, the arrows move the highlight, editing the name or the X
  clears the filter; the typed name never reaches the URL) next to the Ativos/Todos filter, one card per link (status badge, patient, document kind and date linking to
  `/documents/$documentId`, recipient and role, purpose, created, expires, views, last access, a note when a newer
  version exists), "Revogar" with the same confirmation as the document card on active links (it also refreshes the
  document page's list), empty state and Anterior/Próxima paging. Filter and page live in the URL search
  (`?status=all&page=2&patientId=...`); with a patient chosen the empty state speaks of that patient. Copy is in `pt.json` under `sharing.overview`.
- Tests: `ShareOverviewTests` (scoping and discarded patients, status filter, patient filter, paging, counts and newer version) and
  the 401 case in `ShareEndpointTests`.

## 14. Logs and privacy

No token, password, recipient or patient data is written to a log. Tests run the whole public flow with logging at
Trace and search the output. The page path `/s/{token}` and `/patient/s/{token}` is excluded from tracing
(`ShareEndpoints.IsTokenPagePath`), because OpenTelemetry records `url.path`; hosting logs are at Warning, so the
path is not logged. Audit values carry ids only. **Reverse-proxy and static-file access logs are outside the
application and must scrub the `/s/` path** (chapter 20, section 2.6).

## 16. Limits and known gaps

- **Download off does not prevent copying.** The PDF bytes reach the browser either way; the watermark is the real
  deterrent.
- **The viewer is pdf.js (since 2026-11-02).** It replaced an `<object>` viewer that Android Chrome could not render with
  download off. Pages are images on canvases; a recipient on a very large document may wait while all pages draw.
- **The deep-link fallback is not exercised in a published build.** `Program.cs` falls back to each app's
  `index.html`; confirm once at publish. The sharing depends on it.
- **Forwarded headers were not tested with a real proxy.** The startup checks are unit-tested; `ForwardedHeaders`
  with `KnownProxies` is not exercised with a real header.
- **Wrong passwords accumulate with no reset,** by decision; five over the life of the link block it.
- **No geolocation,** by decision (section 11).
- **Not exercised in a browser;** build and lint only, and no `.http` run against a live AppHost.
- **Row lock during Argon2 and render:** one database connection per in-flight attempt, bounded by the limits.
- **Browser-side leaks of the token:** `noindex` and `no-referrer` come from the app's meta tags, so requests made
  before it renders, browser history and static-file access logs (if enabled) still carry the path. `autocomplete="off"`
  is advisory.
- **A transient network or 5xx failure reads as "link indisponível ou senha incorreta"** (no view is used).
