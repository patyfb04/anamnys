# Protected Sharing (F-17 + F-18)

**Date:** 2026-11-01
**Status:** Approved for implementation
**Scope:** Backlog F-17 (disclosure authorization record) and F-18 (tokenized share links). A signed issued document can
be shared with a named recipient through an opaque link and a separate password, only after the provider records the
patient's authorization.

Done when (backlog): sharing is unavailable until an authorization record exists; a signed report can be shared, opened
with a password delivered through another channel, watermarked, logged and revoked, with each step in the audit trail.

Explicitly out of scope (backlog): sending the document by e-mail; any sharing with no authorization record.

## 1. Decisions (agreed with the user, 2026-11-01)

| Topic | Decision |
|---|---|
| Authorization | The provider records: recipient (name and role), purpose, authorization date, how it was obtained (verbal in session, signed term, in writing), an optional attached term, and an explicit confirmation. One authorization per document, recipient and purpose. |
| What can be shared | Signed issued clinical documents only (F-05). No session notes, no received documents. |
| Access log | Date and time, outcome, user agent. No geolocation in this delivery and no IP stored; recorded as a gap (sending an IP to a third party would be a new disclosure; a local database needs a licence and updates). |
| Link | Opaque high-entropy token, stored only as a hash. Password generated by the system, shown once, stored with Argon2id. Expiry 7 days by default, 30 at most. Optional view cap. Download off by default. |
| Recipient | No account. Public minimal page `/s/{token}` in the patient app, `noindex`, nothing about the patient in the URL. |
| Not found | Unknown, expired, revoked and capped links all answer the same 404. |
| Lockout | Five wrong passwords block the link; rate limit per IP. |
| Watermark | Each opening renders the PDF with recipient name, date and time on every page. |
| Superseded documents | A corrected document does not change an existing link: it keeps showing the shared version, and the provider's list says a newer version exists. |
| Archived / discarded | Archived patients cannot get new shares, existing links run until they expire. Discard removes every link. |

## 2. Data

Migration `design/migrations/2026-11-01-protected-sharing.sql` (idempotent, mirrored in `anamnys-db-script.sql`, appended to
every migration test chain after `2026-10-31-record-search.sql`): adds to `DisclosureAuthorizations` and `ShareLinks` what the
decisions need (owning provider, recipient, purpose, how obtained, attached term object key, confirmation; wrong-password
count, blocked time). `ShareAccesses` keeps `CoarseGeo` unused. Audit actions for authorization recorded, link created and
link revoked, with the usual guard. Existing tables and their FKs are reused; the F-06 discard already removes share rows,
verify it, and add the attached term object to its object deletes.

## 3. Server

- `Sharing/` area. Provider endpoints (scoped, audited with ids only): record an authorization for a signed document; list
  authorizations and links for a document with status and accesses; create a link (returns token URL and password once);
  revoke. Attached term stored in the private bucket with an id-only key, scanned like received documents if that is
  cheap, otherwise limited to PDF/JPG/PNG by magic bytes.
- Public endpoints, outside the provider session, anonymous: check a token (same 404 shape), open with a password
  (rate limited, constant-time compare, lockout at 5, counts views atomically against the cap, logs `ShareAccesses`),
  serve the watermarked PDF `no-store`, `X-Robots-Tag: noindex`, inline, or as a download only when enabled.
- Tokens at least 256 bits, URL-safe, hashed with SHA-256. Argon2id through `Konscious.Security.Cryptography.Argon2`.
- No token, password, patient data or recipient in logs. Watermark rendered with the existing QuestPDF document pipeline.

## 4. Apps

- Provider, signed document page: "Compartilhar" flow (authorization form, link options, one-time link and password
  screen with the warning to use separate channels), list of shares with status, accesses and "Revogar". Unsigned
  documents and archived patients: no new share, with the reason.
- Patient app public route `/s/$token`: password form, PDF viewer, download button only when allowed, neutral messages, no
  patient data before the password. No login required.
- Copy in pt.json; hover classes.
